Benchmarks

Copper, timed against the browsers you’d use instead.

Copper, Safari, Chrome and Ardia on the same Mac mini, launched and loaded by one harness that reads every browser from the outside, and the tokens AI agents spend getting the same jobs done in each. Every figure is a median with its range and run count, and the rows Copper loses stay on the page.

Measured 25 November 2026. ★ marks each row’s best median; overlapping ranges mean it’s close.

Launch

With the browser closed, started by open -g, the way a link from another app starts it, in the background.

Memory

Everything the browser runs, added up: the app, its helpers, the GPU and network processes and the pages’ web processes. Read 30 seconds after launch, 10 seconds after the 10th tab loaded, 15 seconds after the 20th, and 30 seconds after closing back to one.

Idle

A minute of doing nothing, right after the 1-tab and 20-tab memory readings; every page runs a one-second timer. With the Mac’s screen locked, Copper and Safari draw nothing here while Chrome and Ardia draw their front tab: read these with the locked screen in mind.

Speed

Speedometer 3.1, Apple, Google and Mozilla’s benchmark of web app responsiveness, served from the same Mac.

Where Copper loses

Where another browser beats Copper’s median. These stay on the page.

  • Cold launch → page painted (link opened from another app): Ardia 383 ms against Copper’s 395 ms (3%).
  • Idle CPU, 1 tab: Safari 0.03% against Copper’s 0.18% (6.0×).
  • Idle CPU, 20 tabs: Safari 0.14% against Copper’s 0.30% (2.1×).
  • Idle wakeups, 1 tab: Safari 1.80 /s against Copper’s 17.6 /s (9.8×).
  • Idle wakeups, 20 tabs: Safari 26.6 /s against Copper’s 35 /s (32%).
  • Idle power, 1 tab: Safari 0.02 mW against Copper’s 0.14 mW (7.0×).
  • Idle power, 20 tabs: Safari 0.08 mW against Copper’s 0.19 mW (2.4×).
  • Speedometer 3.1: Chrome 81 points against Copper’s 62.3 points (23%).
  • Agent tokens, Claude Code: Ardia 3.25M against Copper’s 6.93M (2.1×) over all eight tasks.
  • Agent tokens, Codex: Ardia 2.30M against Copper’s 5.40M (2.3×) over all eight tasks.

How we measure

The Mac

Mac mini (Mac18,5), Apple M6, 24 GB, macOS 27.0.1 (26A434), measured 25 November 2026. Nobody sits at it, so its screen is locked. Other jobs share it, so every run happened while the harness held the Mac’s shared lock (no build or test that takes it could start), and each hold began once the load average was under 2. Median load average as the measurements started: 1.69.

The browsers

Copper 1.0.20261124.117, Safari 27.0.1, Google Chrome 158.0.8127.89, Ardia 0.2.48. Each as shipped, with default settings, in a profile of its own that starts from the same template (one launch, our test page opened, a minute to settle, quit), so every launch restores the same one tab.

  • Copper runs in a test world of its own: the same app, with its own data folder, told to behave exactly as shipped (hidden pages slowed down, App Nap left to macOS).
  • Safari can’t run from a copy or in a profile of its own, and this Mac’s Safari profile belongs to its owner. So it only gets the launch to a window (its Start Page, no address), and its memory and idle runs happen in a WebDriver session, Safari’s own private window set.
  • Chrome runs from Google’s download with its own profile folder and its DevTools port open (that’s how tabs are opened and closed), restoring its last session like the others.
  • Ardia runs from its release download with its own data folder, onboarding marked done and its DevTools port open, not in the background test mode Ardia’s own benchmark gives it.
  • Arc isn’t here: it wants an Arc account at first launch, and nobody can sign in on a Mac nobody sits at.

The locked screen

With the screen locked, macOS calls every window hidden. WebKit then stops drawing pages, so Copper’s and Safari’s pages draw nothing during the idle minutes, while Chrome and Ardia keep drawing the tab in front. That tilts the idle rows toward Copper and Safari by one page’s drawing. Kept drawing (headless, which ignores the lock), Copper idles at 0.96% CPU with one tab against 0.18% with it hidden, 97.8 /s wakeups against 17.6 /s (n=1). Speedometer needs a page that draws, so Copper runs it headless (its pages ignore the lock there, drawn into a window off every screen, which may cost a little less than one on screen) and Safari has no score.

The runs

One harness drives every browser from outside the app, on the same local test page (60 boxes, 120 paragraphs, a one-second timer). Browsers take turns item by item, in an order that rotates each round, so nobody always goes first. A window counts once one at least 300×200 is on screen; a page counts at its first contentful paint, which the page reports itself. Memory is phys_footprint summed over every process the browser runs or macOS holds it responsible for; CPU, wakeups and energy are the kernel’s own per-process counters over the same processes. Each figure is the median of the runs, with the range and the count. So far this page has 1 of the 3 planned rounds: most figures are one run, and n on each figure counts them.

Not measured here

New tab, tab switch and new window need a driver inside each browser, and every browser has a different one; the clicks a person would make need an unlocked screen, and so does power while scrolling or playing video.

The data: bench.json, every run in perf/xbench/results, the harness and its method in perf/xbench.
