# Changelog

What changes in Copper from one version to the next, newest first.

**Unreleased** gathers what is done since the last version, as it lands:
every fix and every addition gets its line the day it is merged. When a
version ships, the section takes its number and date, its gist becomes the
paragraph in `NOTES.md` (what Settings and the updater show), and the list
is what gets posted as the update. What is planned but not done yet lives
in [ROADMAP.md](ROADMAP.md).

## Unreleased

### Added

- **Move in from Safari.** Safari is a source in Move in beside Chrome and Arc. With Full Disk Access, Copper reads Safari's own files: open windows, tab groups and pinned tabs become spaces (private windows never), and bookmarks, the Reading List and history come over from every profile. Without it, Safari's card says so in one sentence and offers **Allow Full Disk Access…**, which opens the right page in System Settings, and **Use an export instead…**: in Safari, File › Export Browsing Data to File… makes a zip, and dropping it on the sheet brings bookmarks, the Reading List, history and passwords, with no permission needed. Passwords come only from the export and go through the same CSV import as Settings › Passwords, so macOS asks nothing. The summary says what stayed in Safari and why: open tabs when only the export was read, payment cards, Safari extensions, password notes and one-time codes. Moving in again adds only what is new, with the same rules as Chrome and Arc. (docs/flow.md, Safari.)
- **Talk to the agent.** The ⌘E pane takes dictation, on this Mac, with Fermion Research's Phonon-2 speech model. Settings › Voice turns it on (off by default): the first time, Copper downloads the 345 MB model once and prepares it for the Neural Engine, about a minute. Hold ⌃⇧D or the mic button beside Send to talk, or choose *Press to start and stop*; the words you are saying show as one muted line above the buttons, and when you stop they go into the message for you to read and send — or, with *Send right away*, are sent at once. Escape cancels and leaves the message as it was. ⌃⇧D only works while the pane is open, and the words only ever go to the agent. Audio never leaves the Mac and is never written to disk. Needs macOS 15. Speech model: Phonon-2 by Fermion Research (CC BY 4.0), derived from NVIDIA Parakeet TDT 0.6B v3; runner: Fermion Research's phonon-coreml (Apache-2.0). ([docs/voice.md](docs/voice.md))
- **Listen: a live transcript in the ⌘E pane.** The waveform button in the pane's header starts it, and a quiet card shows *Pause* and *Stop* (*Forget* once stopped) and opens to show the lines. The pane's agent sees it through a *Live transcript* chip on your question. Agents on this Mac (phi, Claude Code) can read it — with `voice_status` and `voice_transcript`, or `copper transcript --follow` — only when Settings › Voice › *Let agents on this Mac read the Listen transcript* is on (off by default); they can't start Listen or hear audio. The transcript stays in memory only and is never written to disk; *New chat* clears it. It pauses when the pane closes, when the Mac sleeps or the screen locks, and when the mic is unplugged. One mic at a time: dictation is unavailable while Listen holds the mic. Needs macOS 15. ([docs/voice.md](docs/voice.md), [docs/agents.md › Listen transcript](docs/agents.md#listen-transcript))
- **Copper keeps its crashes, and says what it was doing.** At launch it takes in its own macOS crash reports (and upstream's `crash.log`) into `crashes/` in its data folder — the newest 50, each with how it ended, the crashed thread's frames and the breadcrumbs of that run up to the crash: launches and quits, every agent tool call (name, tab, time, ok or the kind of error), page processes that died, and memory once a minute — metadata only, never page content, addresses' paths, typed text or tool arguments. A run that left no quit line and no report (killed for memory, force-quit) is recorded too. `copper crashes` lists them and `copper crashes show N` prints one (works with Copper down); `browser_crashes` gives agents the same; Settings › About shows the last one with Reveal in Finder and Copy Report, and nothing when there are none. Releases now attach their dSYM so `copper crashes show N --symbolicate` can name Copper's frames. Nothing is sent anywhere. ([docs/crashes.md](docs/crashes.md))
- **Delete your history on Copper Cloud.** Settings › Cloud › *Delete history on cloud*: the last hour, 24 hours, 7 days or all time, optionally only one site (with its subdomains), one confirmation, then *Deleted N visits from the cloud*. History on this Mac stays as it is. While History syncs, *Clear History* clears it on the cloud too, and forgetting a page in the History window deletes that page's visits there from every Mac. The cloud never filters history by content: a site or a page is found by this Mac reading the history and naming the visits to delete. Also `copper cloud-history delete [--since 1h|24h|7d|TIME] [--until TIME] [--host SITE]… [--page URL]… | --all` and the MCP tool `cloud_history_delete` (loopback agents only). Needs Copper Cloud 0.8.0; an older cloud says so. Nothing deleted is pushed or pulled again. `./bench cloud selftest` covers it. (docs/cloud.md.)
- **The agent pane's tool-call budget is a setting, and Copper Cloud can set it.** It now takes up to 60 rounds of tool calls per question (was 24, with no way to change it): Settings › Agents › *Tool-call rounds per question*, 1–500. A Copper Cloud that sets the org's number (`"agent": {"max_turns": N}` in `GET /v1/intelligence`, Copper Cloud 0.7.0) wins while you're signed in — the row reads *Set by Copper Cloud: N* — and your own number is back after sign-out. The stop note says where the limit is set. `./bench agent turns N`; `./bench agent selftest` covers it. (docs/agents.md.)
- **Checklist cards for RSVPs and to-dos.** A canvas card (toolbar list tool, or `R`) with a title, one to four columns — *Yes* / *No* to start — and up to sixty rows. One click on a box ticks it and a second click clears it, for anyone who can edit, without selecting or opening the card; each row has one pick. Column headers count the picks, hovering a box says who ticked it and when, and two people ticking different rows at the same moment both stick. Double-click to rename the title, a row or a column; Return in a row adds the next. Agents add and fill them with `canvas_apply` (`rows`, `columns`, `picks`) and read them with `canvas_read`; `update {view:'checklist'}` turns a note that holds a heading and a task list into a card, ticks kept. A card is stored as a note whose text is the list (`### Going`, `- [x] Ann`, `- [x] Bob · No`), so older Copper versions show it as a note with clickable task boxes, and ticks made on either side show on the other. (docs/canvas.md, Checklists.)
- **Chat on shared canvases, with @mentions.** A canvas on Copper Cloud has a chat panel: the chat button beside Share or `C` shows and hides it, and Copper remembers that per canvas. Messages are kept with the canvas, so everyone on it sees them and they are there after a relaunch. Typing `@` lists the people on the canvas — only them — and a picked name shows as a highlight, stronger when it is you. With Copper Cloud 0.6.0 the person mentioned gets a pill over the panels, a dot on the Canvas door, a badge on the canvas and a Mac notification when Copper isn't in front; **Open** shows the canvas with the message lit and marks it read on all their Macs. On an older cloud chat works and mentions show inside the canvas only. Agents read chat with `canvas_read` and post with the new `canvas_chat` tool. (docs/canvas.md, Chat.)

- **1Password, natively.** Settings › Passwords › Password managers now has a 1Password card beside Bitwarden. Copper talks to 1Password through its CLI (`op`), three ways: **Unlock with 1Password** hands the approval to the 1Password app — Touch ID there, no password ever typed into Copper (turn on 1Password › Settings › Developer › *Integrate with 1Password CLI* once); **account password** signs in to an account already on this Mac or adds one (sign-in address, email, Secret Key), with the password and Secret Key passed on stdin and in the environment, never on a command line; and a **service account token** for a Mac nobody sits at, read-only when the token is. The vault's list shows at once and its details load behind it (1,500 items in about four seconds); 1Password logins, one-time codes, identities, cards and custom fields fill exactly as Bitwarden's do, *Save new passwords to* offers Keychain, Bitwarden or 1Password with a vault to save into, and a changed password updates the item rather than adding a twin. Agents sign in and autofill with 1Password items you share in Agent access (off by default) and never receive a secret. The session stays in a file only you can read when *Stay unlocked* is on; Lock wipes what Copper holds first. `./bench op …` and a mock `op` in docs/fixtures/op-mock test it all without an account (docs/passwords.md).
- **Settings, rebuilt, with search.** The panel grows with the window (up to 920 × 700), its pages are grouped — Browsing, AI & agents, Data & privacy, Copper — and each has a heading, a line saying what it is for, and titled sections. Search sits at the top of the rail: ⌘F or just start typing. It reads every setting on every page, forgives typos (*bitwardn*, *dakr mode*), knows other names for things (*adblock*, *mcp*, *dark mode*, *default browser*), groups results by page with the matched letters in bold, and dims the pages with nothing. ↑↓ and Return, or a click, take you to the setting, scrolled into view and briefly lit; on/off settings switch right in the results. `./bench settings search|pick|index check`.

### Fixed

- **Chrome's switch in Privacy & Security stays on.** After updating from an ad-hoc build, macOS kept that build's App Data record, matched nothing against it, and turned the switch back off each time. Allow in System Settings now clears Copper's own stale record first, so the switch sticks.
- **An extension's page can open the web.** 1Password's *Start setup* page did nothing at all when you clicked *Sign in* or *Create your 1Password account*: it sends its own page to start.1password.com, and WebKit drops any load that leaves an extension's page — after Copper had allowed it, without a word. Now an extension's page in a tab that goes to a web address becomes an ordinary tab at that address, a window it opens at one is an ordinary tab that loads (it used to stay blank), and a popup that sends itself to the web opens the address in a tab and closes. Extensions also see the tabs in every space, not only the one on screen: a page in another space was a tab WebKit had been told was closed, so everything its content scripts said to their extension failed with *Tab not found* (1Password listed those among its errors). Proved headless by `docs/fixtures/extension-tabs-e2e.sh`.
- **Mouse-look works in 3D pages and games.** A page that captures the mouse to turn its camera — first-person views, browser games, model viewers, anything on the Pointer Lock API (three.js `PointerLockControls`) — got a refusal in Copper every time, so clicking the canvas did nothing and moving the mouse turned nothing, while Safari and Chrome worked. WebKit asks the browser before it hides the pointer, and Copper never answered. It now does, as Safari does: the page gets the mouse after you click in it, a small *Press Esc to show your pointer* shows for a moment, and Esc, switching windows or apps, or leaving the page gives the pointer back. Only the page in the window you are using can take it — never a tab an agent works in behind the scenes, never a headless Copper. (#52)
- **Move in from Chrome brings what it says, in one steady sheet.** Moving in from Chrome could bring nothing, and the sheet cycled in and out with two states drawn over each other. There were two causes. macOS keeps Chrome's folder private ("App Data"), never asks, and records Copper's first read as refused, and ad-hoc-signed builds lost any grant at each update; Copper showed Chrome as readable and then read nothing. And every way in made its own sheet in every window, looked for browsers again on each redraw, and let the content resize the sheet. Now there is one AppKit sheet, on the window you opened it from, at one size, with a fixed header and footer; browsers are looked for once per opening, off the main thread. When macOS keeps Chrome's folder private, Chrome's card says so in one sentence with **Allow in System Settings…** (Copper looks again when you come back) and **Use an export instead…** for Chrome's bookmarks or passwords file. The summary lists each kind of thing — what arrived, or why nothing did — and stays until **Done**, which lands on the first space the move made. Moving in again adds only what is new: spaces fill, no tab, bookmark or place is brought twice, a window with only new-tab pages makes no space, and Undo takes back only that move's tabs. Imported tabs are no longer closed by Today's clean-up the first time you visit their space, a name you already use gets the right browser's name, and big bookmark files merge in linear time without a pause. Tabs from Chrome open signed in: the sign-ins go to the jar their space uses, and a second Chrome profile's into its own. ⌘W with the sheet up closes the sheet, not the tab behind it, and other shortcuts wait until it is closed. A move you close the sheet on finishes and shows its summary the next time you open Move in, and a Chrome that has never kept a window open says it had none instead of "couldn't read". (docs/flow.md.)
- **Settings works from the keyboard and with VoiceOver, and fits a small window.** Every switch, choice and button can be reached with Tab (when Keyboard navigation is on) and has a name; Space flips a switch, the arrow keys move a choice, and a thin focus ring shows where you are. Settings › Spaces and Extensions fit a small window, with nothing cut off or sliding sideways. ⌘W with Settings open closes Settings, not the tab behind it, and a switch flipped in the search results shows at once.
- **Settings asks first, and says what happened.** Clear history, Sign out of everything, New token, Delete space and Remove extension ask before they act; Clear history and Sign out of everything reach every space's profile. Choosing a downloads folder, asking where to save a download, picking a space's picture and loading an unpacked extension open on the window instead of freezing every window. Intelligence › Check says in plain words what went wrong and what to do next, and forgets its answer when you change the lane, the model or a key. Copper Cloud no longer says *Up to date* when it can't reach the server, and a link code pasted without its fingerprint is called incomplete, with what to do. Password-manager cards can sign out, say *Wrong master password* in plain words, and keep your items when a sync goes wrong. Cancelling the Claude sign-in closes the tab it opened.
- **Passwords and updates in Settings.** You can export your saved passwords to a CSV file after Touch ID; the file is readable only by you. Importing a CSV from Chrome, Safari, Apple Passwords or a password manager says exactly what happened. Sites you told never to offer saving are listed one by one, each with its own Forget. About and Settings › Updates agree on what's new, a failed re-check no longer hides an update that's ready, and Updates shows the release notes before you update. Send Feedback opens a new issue on Copper's own page with your version filled in.
- **Settings search finds more, and is stricter about typos.** *sign out of everything*, *tracking protection*, *update channel*, *change model*, *mcp off*, *beta features* and *ask before download* land on the right setting, and a card you pick lands with its title in view; *font* no longer finds *front*. About lists eight more keyboard shortcuts. *Tabs show: Letters* works with tabs in the sidebar too, *Swipe between spaces* and Labs › Trails say they need the sidebar, Settings › Agents stays still while agents work, and Spaces icons are called what they look like.
- **⌘Z in the agent's composer no longer sends what you took back.** Undo and redo (⌘Z, ⇧⌘Z) in the message field changed the text you saw but not the message Copper kept, so Return or Send sent the text from before the undo. It happened with typed text too, long before voice. What is sent is now always what the field shows.
- **`browser_perf_probe` no longer crashes Copper.** It started the page script from a child task off the main thread, and WebKit's Swift `callAsyncJavaScript` asserts it is on the main queue — so an agent sampling a tab took the whole browser down (`EXC_BREAKPOINT` in `_dispatch_assert_queue_fail`; three times between Oct 1 and Oct 6). The call now runs on the main actor.
- **Chrome extension switches survive Move in.** Flow reads Chrome's legacy state and newer disable reasons across both preference files, installs disabled extensions without starting them, and shows each extension's on/off state in `bench flow scan`.
- **Chrome's account bookmarks move in with Flow.** Signed-in profiles keep their synced bookmarks in `AccountBookmarks`, not `Bookmarks`; Copper now reads both files for every profile and merges matching folders and duplicate sites, with the Chrome bar directly in Copper's bookmark list and Other/Mobile under their own folders. Re-import replaces only untouched items from the earlier import, leaving your own bookmarks alone. `./bench --world NAME flow bookmarks` shows the imported tree; `docs/fixtures/flow-bookmarks-e2e.sh` tests it in a disposable headless world.

- **Settings is fast again.** The rebuilt panel lagged: its shadow was cast from the panel's own content, so every scrolled frame, hover and keystroke re-blurred all of it offscreen; it now comes from a plain shape behind the panel and is drawn once. The panel also stopped redrawing for every tab, find and announcement in the window (it watched the whole browser for one value), the agent-access list reads your accounts once instead of several times per redraw (and builds only the rows in view), duplicate-account merging is linear instead of quadratic (~185 ms per redraw for 800 logins), and the scrolled-header hairline no longer redraws the whole page. `./bench settings perf run|switch|churn|scroll` measures it.

- **A canvas invite that is no longer open leaves the screen instead of failing for ever.** Joining a canvas through its share link closes your email invite to it on the server, but Copper kept showing the invite pill and the Invitations row, and every Join, Decline or Not now then Decline on them got `404` from `POST /v1/invites/:id/accept|decline` and changed nothing until some unrelated refresh. Now a `404` there means the invite is no longer pending (taken up through a link, answered on another Mac, withdrawn), not an error: the invite leaves the pill, the Invitations list and ⌘K, the lists are read again, and Join opens the canvas when you are a member of it already — otherwise the window says *That invite is no longer open*. Joining through a share link also takes any invite to that canvas off this Copper at once. `./bench --world NAME canvas stale accept|decline INVITE_ID CANVAS_ID` answers an invite by id the pill's way, for tests.

- **The agent pane stops paying for the same prompt on every turn.** Each turn re-sends the whole conversation — 40–50k tokens a few tool calls into a question — and Bedrock and Anthropic only cache what a request marks, so every turn paid full price for everything before it (the gateway's ledger showed not one cached token from Copper). Both lanes now mark the end of the system prompt, the last tool, the last message and the previous turn's last message (`cache_control`, at most four), and keep that prefix byte-for-byte the same from turn to turn: bodies are written with sorted keys, and nothing that changes per turn sits before the conversation. Turn two onward reads everything before it from the cache at a twentieth of the price on Opus 5.5 — a 10k-token turn drops from about $0.04 to $0.005 — and a follow-up question reads the whole earlier conversation. A model on the gateway that is not Claude gets no marks, and one that turns them away is asked again without them. `bench agent chat` lists each request's prompt, cached, written and output tokens. (`Fork/PromptCache.swift`, docs/intelligence.md.)

- **Inviting someone to a canvas visibly does something, on both ends.** Inviting someone already invited used to look like nothing happened: the Share sheet kept an *Invite* button and no pending state, and the person invited saw nothing new — their only sign was a pill at the window's foot that any open Settings or History sheet covered, and that never came back once missed. Now every person in the Share sheet says where they stand — *You*, *Owner*, *Member*, *Invited*, or **Invite** — and an Invite click flips the row to *Invited* at once, with what happened in a line right under the field (*Invited Ada — it's waiting for them in Copper*, or *…waiting for them to make an account on ‹host›*). The sheet lists the invites still waiting on the canvas. On Copper Cloud 0.5.0 each one has **Resend** — a reminder that brings the invite back up in their Copper (*Reminded Ada*) — and **×** to withdraw it (the canvas's owner or whoever sent it); on an older cloud the rows say *Invited* without them. The person invited has an **Invitations** list in the Canvas card (Decline / **Join**, which opens the canvas), a dot on the Canvas door, *Join Canvas · ‹name›* in ⌘K, and the pill — now drawn over Settings and every other panel, back on each launch while the invite waits and whenever its sender reminds them (*Ann reminded you about “Roadmap”*). Its × means *Not now*: it no longer declines the invite. `canvas_invite` says *Reminded …* when it reminded someone.

- **History sync can't get stuck on one visit.** A place whose entry was over the cloud's size limit — usually an imported sign-in address tens of kilobytes long — made copper-cloud refuse its whole batch (400), and Copper sent the same 500 visits again after every page you opened, for ever: nothing visited after it ever reached the cloud. Copper now reads the cloud's limits (`GET /v1/info`), measures each visit exactly as it is sent, shortens a title too long to fit and leaves out — saying so in the cloud log — an address too big to store. A request the cloud refuses anyway is split until the refused visit stands alone; that one is skipped and logged and the rest goes up (a cloud that names the entry or a smaller limit is believed at once). Eight refusals in a row with nothing accepted stop the push without skipping anything, and a failed push waits 30 s before the next, then twice as long up to 15 minutes (*Sync now* doesn't wait). The push cursor only moves past visits sent or deliberately left out, and never past now, so an imported visit stamped in the future no longer hides every later one. `./bench --world NAME cloud selftest` runs these cases against a pretend server.

- **Downloads just work.** A file the server marks as an attachment is saved now even when it is a type Copper could draw (a PDF, an HTML page, an image): Gmail's download button — which loads the attachment into a hidden frame — did nothing at all, and a download link opened in a new window left a blank tab. The new tab closes itself once its file is on the way, and you are back where you clicked. A page no longer drops files into Downloads as it loads: a frame inside a page (an ad, a tracker, a widget) only saves what its server marks as an attachment. An error or an empty answer — a 404 with no body, a 500 in an odd type — is never saved as a zero-byte file named after the address; the tab says what happened instead, and a 204 leaves the page alone. And a tab whose address turned out to be a file forgets that address, so visiting the tab again, reopening Copper or the load check no longer fetches — and saves — the same file again (`overview`, `overview 2`, `overview 3`). Rules in `Fork/DownloadPolicy.swift`; `bench downloads policy-check` runs their cases.

- **The agent pane always asks for the newest model.** On the API-key lane Copper now sends the gateway's floating names — `opus`, `sonnet`, `haiku` — so the pane, Jev's text and extract helper and every agent tab follow the gateway to the newest model (Opus 5.5) without an update. A pinned or prefixed name saved by an older build or set from the CLI — `exowatt/opus`, `opus-5`, `claude-opus-5`, `claude-sonnet-5`, `claude-haiku-4-5` — goes back to its float as `intelligence.json` is read; the Claude-account lane, which has no float, gets Copper's current id for the tier. Custom names (`luna`, `gpt-4o-mini`) are kept. Requests on both lanes no longer send `temperature` (which Opus 5.5 refuses), never send a `thinking` block, and leave tool choice on `auto`. Settings › Intelligence and the pane's model menu say which name was sent and which model answered.

- **Moving in from Arc keeps you signed in.** Flow pours every Arc profile's cookies into one jar, and the same cookie often turns up in several profiles. They were set newest first, so the oldest copy won: a long-unused profile's `logged_in=no` signed you out of GitHub and the like, though your main profile was signed in. Only the most recently used copy of each cookie is set now.
- **Links from other apps open again.** A click in Slack, Mail, Forca or a terminal's `open https://…` brought Copper forward and showed nothing new: macOS hands the address to *a* running Copper by bundle id, and with an agent's headless or test-world probe alive — launched from the same bundle, earlier — it was often the probe, which opened the page in a world nobody can see. A probe now hands the address to the main Copper's process by pid (launching it first when it isn't running), the way it already handed on a Dock click. Links also land in the browser window in front — by stacking order, so a key Settings window or panel doesn't count — rather than always the first one, bring back a window from the Dock or from closed, and an `.html`, `.webloc` or `.url` opened with Copper — document types the bundle has claimed all along — opens instead of being turned away. The first window also keeps telling Copper when it is in front after its red button and a reopen, so links, agents and ⌘N stop losing track of it.
- **Coming back to a slept tab no longer throws the window around.** Picking a tab that had gone to sleep (half an hour unlooked-at, memory pressure) showed its last picture while the page was rebuilt — scaled to fill the stage. A picture taken when the stage was wider — before the agent pane opened, before the window was narrowed — made the stage as wide as the picture, the whole layout slid left to centre it and the sidebar went off the window's edge until the page arrived: the "fullscreen" flash. The picture is now drawn at its own size from the page's top-left corner, cut off where the stage ends, on the page's own background colour (read off the picture's edges) where the stage has grown; it is on screen the instant the tab is picked instead of fading in over the window's ground, and it comes down the moment the page has painted (Safari's cue) rather than a fixed moment after the document commits. The sidebar never moves. The rebuilt page now loads when its view reaches the window — AppKit says so — instead of a fifty-try poll, and putting the tab back to sleep or sending it elsewhere within that second cancels the restore's retries and health check, which could otherwise wake it again or replace the next page's navigation.
- **An agent's cursor leaves the canvas about two seconds after its last change.** The named cursor and face an agent gets on a board while it works (⌘E, MCP, `copper` CLI) stayed for two minutes after it was done. Each change is now a two-second lease: every op renews it, the cursor fades over its last moments and is gone — from the board, the top-right faces and the Share sheet's *N here now* alike — and the page that drew it deletes the entry when the lease runs out, when the page closes and when its sync socket drops, so a collaborator who vanished leaves no ghost either. People's cursors are unchanged.
- **One ⌘E pane, with who is driving always in view.** The agent pane is the one place every hand on the page shows — your chat with Copper's agent, a Jev run, phi or Claude Code on the loopback server, a bot through a link. A call another agent made while Jev was running used to replace Jev's run or vanish; a result that came back after its caller's card was archived, or after you pressed Stop, was lost or undid the Stop; and a later tool call could fold into a group above an outside driver's card, out of order. Each caller now keeps its own card in time order, late results land on the right card without undoing Stop, and a band under the header says who is driving, in its colour, with a clock and Stop — one per caller working at once — however far you have scrolled. ⌥⌘J (and ⌘K › Driver Timeline) opens the pane at the newest run instead of toggling it shut, and Stop on a Jev run with no loop left behind it ends the run instead of leaving it *running*.
- **The agent pane finishes big jobs, and never fails in silence.** Asked for a hundred canvas notes with arrows between them, the ⌘E agent did nothing and said nothing: on the API-key lane a reply could only be 2,000 tokens long, the one huge `canvas_apply` was cut off mid-JSON, the half-written call was run with no arguments or dropped, and a turn with no tool call simply ended — so *yes do it* showed *Thinking…* and then nothing. Replies may now run to 16,000 tokens on both lanes (a router model that refuses that is asked again at 4,096), a request waits five minutes instead of two, and a reply that hits the limit anyway is never the end: the transcript says so in plain words, a call cut off half-written is not run and the model is told why and to split the work (at most 40 ops per `canvas_apply`, with its own shape ids so arrows can name them), and the loop carries on until the job is done — or says, after three cut-offs in a row, to ask for smaller pieces. Arguments that aren't valid JSON are answered as an error instead of running as `{}`; a reply with no words and no call says *The model sent back nothing*; *Let me do that now:* with no call is told to make it; ops the board turned away show on the step in red (*3 of 40 not applied — op 7 (connect): no shape n7*); a timeout says what it means.
- **Share sheet works on Copper Cloud 0.2.0: email invites always, no raw errors.** Against a cloud from before share links (copper-cloud 0.2.0) the sheet showed a bare orange *not found*, its people search came back empty, and there was no way left to invite anyone. Copper now reads the cloud's version (`/v1/info`, again on every reconnect): on 0.2.0 Copy invite link, Copy web link and Reset link give way to one quiet line — *Invite links need Copper Cloud 0.3.0 — \<host> runs 0.2.0. You can still invite people by email.* — the directory is never asked, and a pasted or clicked invite link says *This Copper Cloud doesn't support invite links yet (runs 0.2.0).* On every version the field reads *Search people or type an email* (*Type an email to invite* without a directory) and a typed address gets an **Invite \<email>** row; success reads *Invited \<email> — they'll see it in Copper*, and a refusal is a sentence (not an email address, that's you, already a member, can't reach the cloud), never the server's own words. The sheet says *Only you here* instead of *0 here now*, counts you in *N here now*, and its Members list updates the moment someone accepts.
- **Tab now accepts address-bar/command-bar autocompletion and reaches pages normally; only ⌃Tab switches tabs.** A plain Tab used to fall through to *next tab* whenever Copper couldn't tell a page field had the keyboard — a button or link, an iframe's or a code editor's field, a canvas board, or the address field with nothing listed. ### Fixed (Copper)

- **⌘T keeps up with your typing.** On a big history (20,000 places, 236 tabs, measured with `./bench newtab TEXT --type`) every letter froze the window for 100–140 ms, and the history rows arrived up to 400 ms after you stopped. Most of it was nowhere near the card: the History menu sorted all of history for its eight lines every time anything in the browser changed, a keystroke included. That menu now keeps its eight lines until history changes; what is typed and offered lives in an object only the field and the card watch, so a letter no longer redraws the sidebar, the tab strip and the menus; history is ranked in a few milliseconds instead of a hundred, later letters only narrow the earlier matches, and a letter cancels the ranking still running for the one before; the open tabs and bookmarks are read once when the card opens, not on every letter; a row with no site icon stops reading the disk for one on every redraw; and the card no longer springs to its new height after every letter. Typing "github" a letter every 80 ms: main thread busy 900 → 145 ms, longest stall 120–140 → 20–45 ms, dropped frames 7–8 → 2, history rows on the card within 15 ms of the last letter (was 200–400). The card shows the same rows for the same words as before.

- **An update always comes back, and a Dock click always reaches Copper.** After the swap the relaunch used to `open` the app about 100 ms after the old process died, while macOS still listed it — macOS sent the dead process a "reopen" instead of starting a new one, and nothing came back. A headless agent probe running from the same app could likewise swallow a Dock click or `open Copper.app`. Now the relaunch waits until macOS has let go of the old process, always starts a new instance (same world, port and headless switches), confirms it came up, and falls back to starting the executable directly; a Copper run by launchd is kickstarted back under launchd. Every step is in `~/Library/Logs/Copper/update.log`, and a relaunch that did not come back by itself shows in Settings › Updates. Each world now has one process at most (a kernel lock taken before anything is restored), and a probe hands a reopen to the real Copper — activating it, or starting it with a clean environment — instead of keeping it. docs/updates.md.
- **Animated space backdrops keep moving through a space switch or a swipe.** The column now keeps one scene for its whole life: a switch between animated spaces fades the colours (and the clock) to the new space in the shader in about 0.3 s instead of snapping, a still space in between hides and pauses the scene rather than destroying it (before, coming back started a fresh WebContent process and the scene from t = 0), and a swipe no longer starts a second web view for the curtain — the live scene stays under the moving rows, mixing towards the arriving space as your fingers go. The scene's clock is the wall's from a launch-fixed epoch, so a space's scene is always where it would have been had it kept drawing, and changing its speed bends the motion instead of jumping it. After a swipe commits, the arriving space's picture fades into the live column over the settle rather than popping. `./bench backdrop` shows the scene's process, clock and frames.
- **Stop no longer breaks the agent's next question.** Stopping the agent while a model request or a tool call was in flight could leave a tool call in the history with no answer after it, and every later question failed with `router 400: … tool_use ids were found without tool_result blocks immediately after`. The cut-off call is now answered with *Cancelled by the user* before anything is sent, a run that is still unwinding after Stop can no longer write into the next question's history, and a failed request no longer drops the last tool result.
- **⌘K goes to the page first.** A web app with its own ⌘K palette — Tuesday, Linear, Slack, Notion, GitHub — now gets the key, as in Safari: the browser's search opened over it and the app's never did. A page that does not use ⌘K hands it back and the tab search opens as before. `./bench key … --app` reports `pageFirstOffered`/`pageFirstReturned`.
- **⌘← and ⌘→ move the caret when you are typing.** In a page's text box, the omnibox, or the agent's composer they jump to the start and end of the line (⌘⇧ extends the selection), as in Safari; with nothing editable focused they still go back and forward. A key the page hands back with nowhere to go is kept quiet instead of beeping.
- **Middle-click opens a link in a new tab behind the current one**; ⇧+middle-click brings it forward. WebKit numbers mouse buttons differently from AppKit and the check matched the right button instead of the wheel, so the page navigated in place. A ⌘- or middle-clicked `target=_blank` link now stays behind too.
- **Mouse buttons 4 and 5 go back and forward over a page** — in whichever pane of a split the pointer is over. Over the sidebar they switch spaces; middle-click on a sidebar row or favourite closes that tab.
- **The agent and Jev panes are easy to close.** Every header button is a real 26pt door with a hover wash (the split's toolbar too), a second "close all" door appears whenever more than one pane is open, **Close All Panes** (⌘⌥E) and **Jev Timeline** (⌘⌥J) join the menu and ⌘K, and Escape closes the pane nearest the edge when the keyboard is not in a page.
- `./bench key ID TEXT [--app]` presses ⌘/⇧/⌥/←/→/⎋ and can send through the app's key monitor; `./bench ui focus none` hands the keyboard to the window; `./bench mouse back|forward|middle [X Y] [--shift]` clicks the other mouse buttons in-process; `./bench probe` reports `firstResponder` and `lastLinkClick`.

## 1.0 — 23 September 2026

The first version. A browser for the Mac with nothing in the way: tabs in a row or down the side, pinned tabs that keep their place, and one field for addresses and searches. Ads blocked before they load, passwords and passkeys in your keychain, anything on a page hidden for good, reading mode, floating video, Chrome extensions from the Chrome Web Store (macOS 15.4 or later), and tabs that sleep after half an hour. 2.9 MB, on the engine already in macOS.
